Three retro directions for the site

Michael finds the site bland and wants colour and character: retro and overt, not minimalist, from Linux, old video games and analog gear. Here are three directions, each drawn on the real home hero and a real project card at 1280 and 390 px, with its palette and contrast checks, type, motion rules, and what happens to the concierge panel and its memory colours.

P6-02 of the v3 run, 2026-10-21. A recommendation, not a build: nothing here changes the site (the v3 spec, § 1 anti-goals and § 11). Each direction is one motif, carried by the type and the palette first.

How to read this

  • The content in the screens is the site's own copy: profile.ts (eyebrow, tagline, subline), approach.ts (the loop's five steps and their lines), projects.ts (titles, descriptions, metrics, stacks) and concierge.ts (the panel's labels). A white "illustrative" tag marks content made up for the picture: transcript lines, memory counts, meter needles. The costume's chrome is invented and carries no facts: prompts, whoami, man-page headers, window titles, [ menu ].
  • Fonts are named in the CSS with a system fallback and never fetched, so a screen shows the fallback unless the font is installed. The pixel headline in direction 2 and the readout digits in direction 3 are drawn as inline SVG so they look right anyway.
  • Every contrast ratio below is computed from the hex values with the WCAG 2 relative-luminance formula, by the script that built this page. Body text needs 4.5 : 1; large text 3 : 1.
  • The six memory colours (v3 spec § 5, now in globals.css) stay the same hex in every direction; each direction's table checks them on its own surface.
1

Terminal: the site as a tty session

The harness is a Bash driver in tmux, so the site becomes the machine it runs on. The hero is a shell window: whoami prints the name, and the loop prints as a boot log, one [ OK ] per step. Case studies read like man pages. Two phosphors, green and amber, on near-black.

Palette

  • --tty-black #0b0e0a page background
  • --tty-pane #141a13 window and card surface
  • --tty-text #d3e6cc body text
  • --tty-green #7ee36f accent: prompt, headings, links, focus
  • --tty-amber #ffb627 the cursor, comments, a second voice
  • --tty-dim #8a9a84 muted text
  • --tty-red #ff6b5e errors, a failed step
  • --tty-rule #2c3a29 window borders (decorative, not text)

Type

IBM Plex Mono for the name, headings, prompts and labels; IBM Plex Sans for anything longer than a line (tagline, descriptions, case-study prose). Mono display, proportional reading.

Layout

Left-aligned, like a terminal. One window per page, with Linux window chrome (title centred, controls on the right). Square corners everywhere; borders are 1 px rules.

The one motif

The shell: prompts, the boot log, man-page headers. No CRT glow, no scanlines, no matrix rain.

What a hiring manager sees in 10 s

Someone who lives in a terminal and runs a process: the name, the angle, and five steps that each say OK. It reads as engineering before a word of prose.

Where it can go wrong

  • Green on black is the hacker cliché. The amber second voice, Plex Sans for prose and the absence of glow keep it a workstation, not a film prop.
  • Monospace prose tires the eye; the rule is mono for one-liners only.
  • The accent green (#7ee36f) sits near the memory event green (#4ade80). The strip always names each chip, so colour is never the only cue; if they still read as one, the event chip keeps its colour and the accent moves toward the amber.

Motion rules

  • Moves: the amber block cursor blinks after the last prompt; on the first load of a session the boot log prints its five lines once, top to bottom, in under a second; a key press inverts the key for as long as it is held.
  • Feedback only: the active nav item and a hovered key invert (green ground, black text); no hover lift, no glow.
  • Reduced motion: the cursor is a still block; the boot log is printed whole, at once. Nothing types, nothing blinks.
  • Never: scrolling text, falling characters, flicker.

The concierge panel and the memory colours

  • The drawer becomes a tmux pane split off the right of the window: a 2 px green rule on its left edge instead of a shadow, square corners, the same mono top line. Below lg the bottom sheet is a horizontal split, the rule on top.
  • The transcript is a session log: Concierge> in green, You> in amber, the usher's "Taking you to …" notice in muted italics (D94). The message box is the last prompt, with the same cursor.
  • The memory strip is tmux's status bar. The six memory colours are already terminal colours (cyan, yellow, green, red, magenta and a violet that stands in for ANSI blue: close to the eight ANSI colours), so they stay exactly as they are and read like ls --color. All six pass on --tty-pane (table above).
  • The tabs are tmux's window list; the selected one inverts. Latency stays the current table (LatencyPanel), set in Plex Mono with its digits tabular.
  • /talk is the same pane at full width: the window, with the pane as its whole body.

Cartridge: a vintage console on a CRT

A home console from the late cartridge era. The name is set in chunky pixel type with a red drop shadow, the loop is a row of stage tiles with cartridge-label colour bands, and every project card is a cartridge with a light label. The selection cursor is the menu's ▶. Scanlines sit over the screen at low opacity and go away under reduced motion; the concierge lives inside a CRT bezel.

Palette

  • --crt-void #0f0d1c page background
  • --crt-glass #1d1a33 surfaces, the cartridge body
  • --crt-phosphor #f3efe1 body text, the cartridge label
  • --crt-haze #a9a3c7 muted text
  • --cart-yellow #f6c945 accent: links, focus, the menu cursor
  • --cart-red #e5483d label block, the headline shadow
  • --cart-blue #4f86f0 label block
  • --cart-ink #16131f text on label blocks

Type

Press Start 2P for headings only (the name, a section heading, a cartridge's short title); Atkinson Hyperlegible for everything else. Pixel type for a few words, the most legible face available for the rest.

Layout

Left-aligned hero, then a full-width row; blocks with small radii (4 px) and hard, offset shadows that collapse when pressed, like a console's rubber buttons.

The one motif

The cartridge label: colour bands, a light label, a short title in pixels. The CRT is the frame, not the content.

What a hiring manager sees in 10 s

The most personality of the three: a person who built this for fun and still kept it readable. The angle and the loop are as visible as in direction 1; "engineering" reads second, "play" first.

Where it can go wrong

  • Pixel type is unreadable in a paragraph and wide in a heading: Press Start 2P is roughly as wide as it is tall, so the Agent Harness title (66 characters) would run to about four lines in a 316 px card at 16 px. It is used for short words only; the full title stays in Atkinson.
  • Scanlines dim the page. Here they darken one row in three by 4.9 % and cost little contrast (the faintest body pair, --crt-haze on --crt-void, is 7.30 : 1 in a darkened row against 7.99 : 1 flat), but they must never get stronger over the concierge's transcript.
  • It risks reading as a game rather than as work, the opposite of what the spec's 10-second test asks for (v3 spec § 11) for the readers brand.md puts first.

Motion rules

  • Moves: once per session, the screen powers on: a bright horizontal line opens to the full page in about a quarter second. Buttons drop onto their shadow while pressed. The ▶ cursor jumps to the hovered or focused nav item.
  • Feedback only: a chip that changed in the memory strip blinks its colour block once, as today's pulse does.
  • Reduced motion: no power-on; the scanlines are off (this page does it: try it with the setting on); the cursor moves without travel; buttons change colour instead of moving.
  • Never: flicker, rolling bars, screen shake. A flicker is the CRT effect people expect and the one that can trigger seizures (WCAG 2.3.1).

The concierge panel and the memory colours

  • The drawer is a portable TV: a plastic bezel (#2a2646, decorative) around a rounded screen. The bezel's foot carries a power light, lit while a call is live, in the same red as the pill's live dot (D87) rather than the events green.   • /talk shows the same TV at full size, centred, the way a console menu fills the screen.

Mixing desk: analog hardware

A piece of studio gear: brushed faceplates with screws, lowercase labels silkscreened in mono, keys that light, a seven-segment readout for a project's number. The loop is a five-step sequencer, the thing a drum machine uses to run a loop; the concierge is a rack module whose Latency tab is a row of VU meters. Warm orange and cream on charcoal.

Palette

  • --desk-charcoal #1b1a18 page background, meter windows
  • --desk-panel #292723 faceplates and cards
  • --desk-cream #efe6d2 body text, meter faces
  • --desk-silk #aba190 muted text, silkscreen labels
  • --desk-orange #ff8a2a accent: links, focus, lit keys, readouts
  • --desk-led-green #86e08f signal present
  • --desk-led-red #ff6a55 over budget, the meter red zone

Type

Barlow Condensed for the name and headings, Barlow for prose, Space Mono for the silkscreen labels; DSEG7 for the readout digits only.

Layout

Faceplates on a charcoal rack: one plate per section, screws in the corners, a 6 px radius. Content left-aligned to the plate's inner margin.

The one motif

The lit key and the LED: state shown by light. Knobs appear nowhere on the page, because nothing on it turns: a deliberate departure from the v3 spec § 11, which names knobs as a motif.

What a hiring manager sees in 10 s

Craft and warmth: something made with care, by someone who likes tools. The loop as a sequencer says "a process that repeats" without a word. The agentic angle reads from the copy, not from the look.

Where it can go wrong

  • Skeuomorphism ages fast and costs the most: screws, brushed metal and keycaps are component work, not tokens, and a half-done version looks like a theme.
  • The texture can muddy text. The brushing is 3 % white on a 3 px period, under the 5 % ceiling below; any more and the silk labels lose their margin.
  • It says "music" (Michael's DJ crate project fits it) more than "agents", so it pulls the angle sideways.

The concierge panel and the memory colours

  • The drawer is a rack module: a brushed plate with four screws, the transcript in a recessed well, Guide me as a real toggle switch (D94), Minimize and the tabs as keys. Below lg the bottom sheet is the same module turned on its side, its screws on the top edge.
  • The Latency tab is a bank of VU meters. One meter per timing step of a turn in today's LatencyPanel (whole turn, end of turn detected, speech to text, first token, first audio, memory on the turn path); the drawing shows four of them. Its other rows (prompt tokens from cache, memory preload, background extraction, history compacted) are a share, one-off timings or a yes/no, so they stay as text under the meters. The needle is this turn's milliseconds against a budget per step; the red arc is over budget; the median would be a thin orange peak-hold needle (not drawn here). The budgets come from measured p95s, so until docs/notes/voice-concierge-todo.md is done the meters have no budget and the tab stays the table.
  • The meters are pictures of a number, so the number stays: each meter's value and median would sit under it as text (not drawn here, since nothing is measured), and the table remains the screen-reader and print version, as the /skills List view is for its graph.
  • The memory strip is a row of five channels, each an LED in its kind's colour with its name and count under it. On real desks LEDs come in every colour, so the cyan, violet and magenta sit fine next to the orange. All six pass on --desk-panel (table above), with the smallest margin of the three directions.
  • /talk is the module at full width with the meters along the top, like a meter bridge over a console.

Best practices for a site with character

Character comes from a few strong decisions held everywhere, not from adding effects. These rules apply to whichever direction ships.

  • One motif per page. Pick the shell, the cartridge or the faceplate, and let it carry the page. A page with a boot log, a CRT bezel and a VU meter has three motifs and no identity. The concierge panel may carry its own variant of the same motif; it never brings a second one.
  • Legibility first. The display face is for a few words; everything a hiring manager reads is in a face built for reading, at 15 px or more on the phone, never below the size of today's body text by more than a pixel. A motif that costs a reader a sentence has to go.
  • Motion as feedback, not decoration. Things move when someone does something (a key goes down, the cursor jumps to the focused item, a memory count changes) or once, on arrival (the boot log, the power-on, the sequencer). Nothing loops on its own except a cursor, and that stops under reduced motion.
  • A real type scale. A short, fixed list of sizes, each with one job (name, section heading, lead, body, label, small), used the same way on every page; each direction lists its own. When the pass is built, pick them from a modular ratio (about 1.25 at 1280, 1.2 at 390) rather than by eye. Character type needs more discipline than a neutral face, not less.
  • Textures at low opacity. Scanlines, brushing and grain change a pixel by 5 % or less (direction 2's scanlines darken one row in three by 4.9 %; direction 3's brushing lightens one column in three by 3 %) and never push a text pair under its threshold. Check the ratio at the darkest and the lightest point of the texture, as the notes under directions 2 and 3 do.
  • Honour reduced motion and AA. Every animation has a still state under prefers-reduced-motion; no effect flashes more than three times a second (WCAG 2.3.1); body text passes 4.5 : 1 and large text 3 : 1 on every surface it sits on, memory colours included (checked per direction above).
  • The data stays the source. A costume changes how projects.ts and approach.ts look, never what they say: terminal chrome around real copy is fine, invented output is not (no made-up logs or command results presented as real), no invented scores, no fake screenshots (brand.md). Where a mockup needed a number it did not have, it says "illustrative".

References: WCAG 2.2, Understanding contrast (minimum), non-text contrast (for borders, LEDs and focus rings, 3 : 1), three flashes or below, and MDN on prefers-reduced-motion. For how far a CRT costume can go (and why the site should stop well short), cool-retro-term; for hardware as a design language, teenage.engineering.

Recommendation: 1, the terminal

Ship direction 1. It is the only one whose costume is the subject: the site's headline is agentic systems, the flagship project is a Bash driver that runs agents in tmux overnight, and the loop really is a sequence of checks that pass or fail. A boot log of Spec, Context, Build, Verify, Learn says what the site is about before anyone reads it. It is also the most legible of the three and the cheapest: most of it arrives as tokens, the memory colours need no change, and the site already ships a monospace face.

Why not 2: it has the most character and the weakest first ten seconds for a hiring manager; the pixel face constrains every heading. A cartridge could still appear once, as the art for the DJ crate or HitList project page, where play fits.

Why not 3: its best idea, the latency panel as VU meters, depends on measured budgets that do not exist yet, and the rest is the most component work for the least story. Keep the meter idea for /talk after the concierge is measured.

How it ships: a token-only pass first

One PR that changes only src/app/globals.css and the font loading in src/app/layout.tsx; no component changes, so no test that pins markup moves (only the token test and the colour pins in step 1), and the diff is easy to review on the preview URL.

  1. Colours in the @theme inline block: --color-background → #0b0e0a, --color-surface → #141a13, --color-surface-alt → #1c2519 (body text on it 12.02 : 1), --color-foreground → #d3e6cc, --color-muted → #8a9a84, --color-accent → #7ee36f (with --color-accent-dim → #5fc052, the primary button's hover fill, black text on it 8.46 : 1, and --color-accent-glow → the accent at 15 %), and a new --color-accent-2 #ffb627 for the amber. The six --color-mem-* stay. design-tokens.test.ts checks them against today's surface and background and pins those two hex values (#12121a, #0a0a0f), so the pass moves its pins to the new surfaces and adds the foreground, muted and accent pairs from direction 1's contrast table. Colours written outside the theme keep today's cyan and near-black until changed by hand: NodeGraph.tsx (the hero's canvas), FloatingLogos.tsx (its hover colour, pinned by FloatingLogos.test.tsx), the Open Graph image (opengraph-image.tsx) and themeColor in layout.tsx (pinned by layout-metadata.test.ts); the pass changes them, and those pins, in the same PR, or the hero keeps a cyan graph on a green page.
  2. Type: swap Geist and Geist_Mono for IBM_Plex_Sans and IBM_Plex_Mono from next/font/google (Plex Mono is not a variable font, so it needs its weight list: 400, 600 and 700 here), which downloads the files at build time and serves them from the site, so no visitor's browser fetches Google (Next.js fonts). No new npm dependency, but a new D<n> all the same, since it changes every page. The hero name stays in the sans face until the component work, so this PR touches no component.
  3. Radii: Tailwind 4 reads --radius-* from the theme (Tailwind theme variables), so setting --radius-sm through --radius-2xl to 0–2 px squares every card at once; bare rounded (the hero's two buttons, the decision-log tags) reads the older --radius, so that one is set to 0 too; rounded-full stays round for the pill and the chips.
  4. Check: the suite, the smoke run, the contrast test, and a capture of every page at 390 and 1280 (node .harness/captures.mjs) for Michael to compare against docs/screenshots/v3/.

Then component work, one PR each, in order of how much each one says: the hero's boot log (MethodStrip's costume, with the reduced-motion still state); the man-page ProjectCard; the shell window around page content; the concierge as a tmux pane. Each ships with its 390 capture.

How this file was checked

Self-contained: inline CSS and inline SVG only, no scripts, no external stylesheets, fonts or images; every font is named with system fallbacks and never fetched. Rendered in headless Chromium at 1280 and 390 px wide, once with prefers-reduced-motion: reduce, with a one-off Playwright run: 0 console errors, 0 page errors, 0 requests outside the file, and scrollWidth no wider than the viewport. Every URL was fetched with curl -sIL -o /dev/null -w '%{http_code}'; the codes are in the comment at the end of this file.
