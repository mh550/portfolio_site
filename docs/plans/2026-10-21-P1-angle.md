## Loop strip

The hero strip and `/about`'s How I work read a new `loopSteps`; `methodSteps` and `MethodStepId`
(`diagnose` … `simplify`) stay as they are for the case-study anchors (`getCaseStudyAnchors`), `/evidence` and the
six written case studies.

```ts
// src/lib/data/approach.ts
export type LoopStepId = 'spec' | 'context' | 'build' | 'verify' | 'learn';

export interface LoopStep {
  id: LoopStepId;
  label: string;
  line: string;
  /** The principle whose first linkable example is this step's one link on /about (D77). */
  principle: Principle['id'];
}
```

The five rows, word for word from spec § 2, with the principle each uses:

| id | label | line | principle |
|---|---|---|---|
| `spec` | Spec | I write down what done means before anything is built. | `decisions-explicit` |
| `context` | Context | Every session starts fresh, from state kept on disk, not from memory. | `automate-bookkeeping` |
| `build` | Build | Test first, one feature at a time, the smallest system that fixes the real problem. | `simplify-after-use` |
| `verify` | Verify | An independent check, with evidence per step, before anything merges. | `verify-what-the-human-sees` |
| `learn` | Learn | Every run is measured and written down, and the next plan reads it. | `fakes-mirror-reality` |

**One example link per step.** The rule: the first example of the step's principle that has a page, via
`resolvedExamples(principle)` then `exampleHref(example)` (the first example whose `exampleHref` is defined). A
helper in `approach.ts`, `loopStepExample(step): PrincipleExample` (throws if a principle has no linkable example,
so a data change that breaks it fails the build and the test, not the page). Resolved on this tree (checked with a
throwaway Jest file against `resolvedExamples`, 2026-10-21):

| step | href | link text (the example's first sentence) |
|---|---|---|
| spec | `/projects/agent-harness#decisions` | The harness keeps a numbered decision ledger. |
| context | `/projects/agent-harness#decisions` | In the harness a deterministic bash driver does all the git bookkeeping, because a script does that and a prompt might not. |
| build | `/projects/home-media-server#simplify` | I built four download-quality tiers, used them, then replaced them with one rule: lossless or 256 kbps and up. |
| verify | `/projects/home-media-server#lessons` | After the first night every count matched, 859 = 859 = 859, while 92 titles were still wrong on my phone. |
| learn | `/projects/agent-harness#lessons` | The harness broke its own rule. |

Spec and Context share a destination (both principles list the harness's decision ledger first); their link texts
differ, so the two links are distinguishable. This is the rule as specified; Michael can pick a different
principle per step in one line of data (question in the P1-01 progress entry). The link text is the example's first
sentence (`text.split(/(?<=\.)\s/)[0]`): every number in it already passes `claims-on-linked-page.test.ts` for the
same example on `/approach`.

**`MethodStrip`** keeps its markup and its two modes (D31: labels only below md in the hero; `showLines` shows the

`examples?: Partial<Record<LoopStepId, { href: string; text: string }>>` renders, under a step's line, one
`<a>` with the shared `focusRing` classes; only `/about` passes it. The list label stays a prop: the hero keeps

Deterministic output (fixed key order, no timestamp), so a second run leaves `git status` clean. The version in the
header is read from `node_modules/simple-icons/package.json` via `fs` (the package's `exports` map blocks
`require('simple-icons/package.json')`). `package.json`: `"logos": "node scripts/logos.mjs"`; `simple-icons` moves
from `dependencies` (`^16.9.0`) to `devDependencies` at exactly `16.9.0` (lockfile updated with `npm install`), so no
`src` file imports `simple-icons` after P1-03.

`<Logo name="python" decorative />` renders `aria-hidden="true"` and no `<title>`. `className` passes through.
FloatingLogos keeps its own `role="img" aria-label` svg inside the `aria-hidden` wrapper (its tests read the
labels), or renders `Logo` with an `aria-label`; either way the labels are the "label on the site" column.
